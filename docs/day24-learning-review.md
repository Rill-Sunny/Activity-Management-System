# Day 22 学习补充：递归、进程与死锁

本页提供附件安排的算法与计算机基础复习材料。材料已准备不代表学习者已完成复习或练习。

## 二叉树递归（建议 60 分钟）

递归函数先定义“输入一个子树，返回什么结果”，再确定空树结果和合并方式。例如最大深度的空树深度为 0，非空树深度为左右子树深度较大值加 1。

```java
int maxDepth(TreeNode node) {
    if (node == null) return 0;
    return 1 + Math.max(maxDepth(node.left), maxDepth(node.right));
}
```

每个节点访问一次，时间为 O(n)；调用栈空间为 O(h)，退化链状树可达 O(n)。练习前序、中序、后序遍历，再用后序递归实现高度与平衡性检查。平衡性检查可返回高度，使用 -1 表示已不平衡，避免每个节点反复计算子树高度。

建议安排：15 分钟复述递归定义和边界，25 分钟独立实现最大深度与平衡二叉树，20 分钟用空树、单节点、链状树、左右高度差为 2 的树手工验证。

## 进程、线程与死锁（建议 30 分钟）

进程拥有独立地址空间；同进程线程共享堆等资源，各有调用栈。Day 24 的 app-a、app-b 是两个独立 JVM，Java synchronized 只能协调各自进程中的线程。它们需要数据库锁、共享存储原子操作及唯一约束才能协调同一订单。

死锁的四个必要条件是互斥、持有并等待、不可抢占和循环等待。例如事务一先锁 Order 再等 Activity，事务二先锁 Activity 再等 Order，会形成环。项目取消入口不同时逐单持有 Order 锁，后台单项处理另开事务，降低与支付的反向等待风险。

数据库死锁回滚与锁等待超时不同。遇到超时要记录等待 SQL、锁持有事务、连接和 fixture 生命周期，不能直接加大超时。

复习后独立回答：为什么两个容器中的 synchronized 无法防止超卖？为什么只重试一条失败 SQL 不等于重试整个交易？为什么取消接口先提交门禁，再分批退款？
