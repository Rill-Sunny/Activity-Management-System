# Day 23 取消设计冻结

取消是不可逆的生命周期变更，退款完成是独立状态。同步事务只锁发布者、Activity 和 Session，记录事件、范围、批次与 Outbox，不获取 Order 或逐个资源锁。

允许取消 PUBLISHED 活动内 SCHEDULED 且尚未结束的场次（包含进行中的场次）；活动取消只覆盖这些场次，保留 FINISHED、已结束及此前取消场次的历史。相同 requestId 和内容返回同一事件，不同请求不能覆盖已取消对象。活动类型属于 Activity；FREE 隔离测试使用独立活动。

取消事件关联一个批次和不可变 Session 范围。任务按 ORDER、TICKET、RESERVATION、GIFT 四阶段使用主键游标，每页 50 项。枚举全部相关历史对象后由处理器按最新状态决定效果，避免因退款状态变化漏扫。每项具有唯一业务键、数据库租约、认领令牌、有限重试和人工重试入口。扫描器补偿 MQ 不可用、剩余分页与过期租约。

取消退款使用原成交价，费率零。取消前已成功退款不补退；已接受但尚未成功的普通/改期报价保留金额和历史，以 CANCELLATION_SUPERSEDED 结束旧申请，再建立取消报价。旧报价不能在取消后按普通费率成交。新取消报价、退款资源效果和任务成功标记在同一事务提交。自动退款允许处理已停用买家的合法退款，不伪造登录身份。

FREE 预约恢复名额一次。GIFT 保留分配历史，座位标记 GIFT_CANCELLED，取消占用仍属于赠票专属池，不转入公开可售池。有效参与判定同时检查生命周期，后台尚未处理也不能参与。

限定商品继续通过票务退款资格事件触发 Day 20 售后。资格查询排除取消场次；普通公开商品及其他正常场次不被取消批次直接退款。已发货商品等待退货验收，取消批次完成表示票务资源收敛、资格事件已持久化，商品售后状态单独查询。

数据库时间是唯一计时依据。认领事务短提交，业务事务锁定自己的任务并核对令牌，之后按 Order → Account → Activity/Session → 退款声明/资格保护 → 限购 → Zone → Seat → Ticket 执行；批次汇总在业务提交后单独更新，避免批次与任务锁反序。

最终实现中，单场次取消也取 Activity X，以阻止活动范围商品资格在取消提交后继续付款。白名单维护取得 Activity 根锁后重新读取 Session 状态。内部退款使用随机请求 ID，持久化任务负责幂等，避免与买家可提交的请求键空间冲突。
